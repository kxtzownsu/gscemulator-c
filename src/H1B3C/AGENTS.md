# src/H1B3C

H1B3C is the Haven chip backend. Its entry points use the `Havn_` prefix.

- Public hooks are declared in `include/H1B3C/emulator.h` and wired through `get_chipemu` in `src/main.c`.
- `Havn_Initialize(void)` must set `ctx.chipemu.ready = true` only after setup succeeds. `main` exits through `emu_exit` when `ready` is false.
- `Havn_Initialize` stores the engine in `ctx.uc`; `Havn_EndEmulation` closes it and clears the pointer so repeated calls are safe. `Havn_Reboot` saves the persistent flash, stops the component workers, closes the engine, clears `ctx.component_count`, reinitializes the backend, and restarts the USB proxy on T0.
- `Havn_Initialize` uses `ctx.firmware.bootrom` when `ctx.firmware.useBundledROM` is false. With `BUNDLED_H1B3C` defined, it sets `useBundledROM`/`useBundledFW` when the matching path is empty, and `load_firmware` copies `BUNDLED_H1B3C_BOOTROM_BIN`/`BUNDLED_H1B3C_FIRMWARE_BIN` into the ROM/firmware regions. A failed read or oversized bundle exits with `RC_CHIPEMU_FAILED_INIT`.
- `H1B3C_EssentialMemoryArray` in `src/H1B3C/memory.c` lists ROM (RX), SRAM (RW), INFO0/INFO1 (RW), and PROG (RWX). ROM and PROG are marked `ESSENTIAL_MEMORY_ROM` and `ESSENTIAL_MEMORY_FIRMWARE`.
- `endorsement-cert.c` holds the production endorsement seed and RO certificate blob from `gscemu-upstream/src/haven/endorsement_cert.py`. `Havn_Initialize` writes the seed into INFO1 at `0x600` and the 2 KiB certificate blob into PROG at `0x3800`, before the firmware runs. It also replaces the test endorsement CA modulus in PROG with the production modulus: 2016 images only trust the test root, while the installed blob is production-signed. The patch scans PROG after `FlashPersist_Apply`, so persisted images get it too.
- `Havn_Initialize` assigns the table to `ctx.essential_memory`, calls `map_essential_memory()`, then calls `load_firmware()` with the `BUNDLED_H1B3C_*` arrays under `BUNDLED_H1B3C` or NULLs when H1B3C is not bundled. INFO1 remains a chip-local write.
- `Havn_Initialize` calls `set_sp_pc(ctx.uc, FLASH_ROM_BASE)` after the flash writes. `set_sp_pc` sets SP/PC; `Havn_StartEmulation` sets the Thumb bit.
- `flash-persist.c` owns the persistent flash files. By default it uses `$HOME/.local/share/gscemu-c/flash/{info0,info1,prog}.bin`; `--flash_dir` overrides the directory and `--no-persist` disables file access. Missing files are created from the defaults (INFO0 `0xFF`, INFO1 `0xFF` with the endorsement seed, PROG firmware with the RO certificates). `Havn_Initialize` applies the files before starting the guest, `Havn_Reboot` and `Havn_EndEmulation` save them, and saved files win over `-f` because they hold the guest's NVMEM changes.
- `init_unicorn` installs the memory fault hook after `uc_open` and the Cortex-M3 model setup, so unmapped/protected accesses log the address, access type, and PC.
- `Havn_StartEmulation` runs on T1, checks `memory_fault_occurred()` after `uc_emu_start`, and reports failures with `runtime_fault` before inspecting the engine error. It returns instead of exiting.
- `ctx.firmware.progfw` / `--firmware` is loaded into the firmware region by `load_firmware`.
- `proxies.c` owns the privileged proxy startup. `H1B3C_StartProxies` performs the root/module checks, asserts the CCD strap (`GPIO0.5` low) when the USB proxy is enabled, and starts `vtpm-proxy` (`tpm-proxy.c`) and `usb-proxy` (`usb-proxy.c`). `H1B3C_StopProxies` stops and joins both and runs from `Havn_EndEmulation`. Non-root runs skip both.
- Peripherals live in `src/H1B3C/peripherals/`. Each `X_Initialize()` registers a `Component` and `initialize_peripherals()` maps the `MmioRegion` table before `ready` is set. `component_register_threaded` starts an opt-in worker; `component_register` keeps the handler inline on T1.
- Register bases and offsets belong in the matching `include/H1B3C/peripherals/<name>.h`; `DEFAULT_REG_LENGTH` in `H1B3C/peripherals.h` is the MMIO region size for every peripheral except PMU (`REG_PMU_LENGTH`, `0x20000`). Keep offsets 4-byte aligned.

MMIO register rules:

- Every handled offset must be a named `REG_<COMPONENT>_<REGISTER>_OFFSET` macro.
- A repeated register array is the only allowed range handler. Its count must end exactly at the next register, and the header must `_Static_assert` that. Shrink or split the range instead of widening it over an adjacent register.
- Dispatch special registers before the range handler. Runlevel, lock, clear-on-write, trigger, constant, read-only, and write-once all qualify.
- Unknown offsets must call `component_log_unhandled`. The only catch-all is FUSE blank reads/writes. Document any new exception here.
- Check every new register against `hw_b1_regdefs.h`, the upstream component handler, and `regdefs/registers.py`.
- Run `.opencode/skills/audit-mmio/scripts/audit-mmio.py` before and after register changes. A passing boot is not proof; the ROM only touches the registers it uses.
- `M3` is mapped at `REG_M3_BASE_ADDR` (`0xE0000000`, size `DEFAULT_REG_LENGTH`) and handles `DWT_CTRL`, `DWT_CYCCNT`, `CPUID`, `ITCMCR`, `DEMCR`, `CCR`, `SHPR1/2/3`, `SHCSR`, `CFSR`/`HFSR`/`DFSR`/`MMFAR`/`BFAR`, the SysTick registers, and the NVIC `ISER`/`ICER`/`ISPR`/`ICPR`/`IPR`/`STIR`. The ITM, DWT counter/comparator, and FPB blocks (`0x0..0x2FFF`) are a flat storage array so debug reads do not fault. `DWT_CYCCNT` counts 24 MHz cycles since emulation start; `CPUID` reads `0x410FC331`; `ITCMCR` reads back `7` after any write. `VTOR` writes clear the previous image's pending/enabled IRQs. `CFSR`, `HFSR`, and `DFSR` are write-1-to-clear. `ICSR` is write-1-to-clear, `AIRCR` accepts the `0x05FA` key and `SYSRESETREQ` to request a reboot, `MPU_TYPE` reads `0x800`, and the `SCR`, `AFSR`, MPU, and debug-core registers are storage.
- `M3` SysTick counts down from `SYST_RVR` at 24 MHz, sets `SYST_CSR.COUNTFLAG` on wrap (cleared by reading `CSR`), and pends exception 15 when `TICKINT` is set. `SYST_CALIB` reports 240000 ticks per 10 ms. A `SYST_CVR` write re-arms the counter.
- `M3_TakeException(ipsr, primask, faultmask)` polls SysTick, merges pending system exceptions and enabled IRQs, and returns the highest-priority exception that can preempt the current `IPSR`. Priorities come from `SHPR1/2/3` and `IPR` (3 implemented bits, 0 = highest); `Reset`/`NMI`/`HardFault` are fixed at -3/-2/-1. `PRIMASK` blocks configurable priorities and `FAULTMASK` blocks everything except NMI and HardFault. The pending bit is cleared when the exception is taken. Exception frames force `EPSR.T` (Unicorn reports `XPSR` without it in the SVC hook), and exception return clears `FAULTMASK` because `svc_handler` sets it and relies on the hardware to clear it. `Havn_StartEmulation` installs `UC_HOOK_INTR` (SVC entry, exception return, and SVC priority escalation to HardFault), `UC_HOOK_CODE` (skip `WFI`), and `UC_HOOK_BLOCK` (poll TIMELS and GLOBALSEC, then deliver the winning exception, including into handler mode for nested IRQs).
- `M3_EscalateFault(kind, status)` sets the matching `CFSR` byte and returns the handler for `MemManage`/`BusFault`/`UsageFault` when `SHCSR` enables it, otherwise HardFault with `HFSR.FORCED`. `Havn_StartEmulation` escalates `UC_ERR_INSN_INVALID`, `UC_ERR_EXCEPTION`, and unaligned-access errors through it and re-enters emulation; a second fault in NMI/HardFault stays fatal.

- `FUSE` is mapped at `REG_FUSE_BASE_ADDR` (`0x40450000`, size `DEFAULT_REG_LENGTH`). Reads return the matching `fuse_defaults` value or `REG_FUSE_BLANK_VALUE` (`0x55555555`); writes are ignored and only logged at verbose level, matching the read-only eFuse.
- `GLOBALSEC` is mapped at `REG_GLOBALSEC_BASE_ADDR` (`0x40090000`, size `DEFAULT_REG_LENGTH`). The region-control window `0x0..0x2CC` is one storage array; a static assert keeps `REG_GLOBALSEC_REGION_COUNT` from growing over the permission registers. `CPU0_S_PERMISSION`, `CPU0_S_DAP_PERMISSION`, `DDMA0_PERMISSION`, and `SOFTWARE_LVL` (`0x2D0..0x2DC`) are separate runlevel registers that reset to `0x55` and drop one level (`0x55`, `0x3C`, `0x33`, `0x00`) on every write, ignoring the written value. `ALERT_INTR_STS0/1` are write-1-to-clear. `ALERT_FW_TRIGGER` accepts `0xA9`, which triggers the four FW alerts (`GLOBALSEC_FW0..3`, indices 19-22). Alert `N` sets its status bit, pends IRQ `18 + N` (plus the 3-IRQ gap above index 18), pends NMI when enabled, increments the enabled group counters, and arms the enabled delay counters. Group counters pend IRQ 36/37/38 when they reach the threshold. `ALERT_CFG_LOCK` freezes the enable/threshold/length registers. A delay counter loads `ALERT_DLYCTRn_LEN`, counts down at 24 MHz, and reports `RC_CHIPEMU_ALERT_SHUTDOWN` when it expires with `SHUTDOWN_EN`; `ALERT_DLYCTRn_CLEAR` disarms it. `GLOBALSEC_Poll` runs from the M3 block hook. `DUMMYKEY0..2` (`0x9598`, `0xAF04`, `0xB2AC`) back an array. `SB_COMP_STATUS`, `SB_BL_SIG0..7`, and `SIG_UNLOCK` are custom; `SIG_UNLOCK` forces `SB_COMP_STATUS` true to skip the RSA path. `HIDE_ROM` (`0x40D0`) is write-once. `INT_ERR_FLAGS` is write-1-to-clear, the CPU/SRAM/DSPS/DUSB error-history and parity registers are storage, and `VERSION` (`0x40DC`) reads `0x59010913`.

- `PMU` is mapped at `REG_PMU_BASE_ADDR` (`0x40000000`, size `REG_PMU_LENGTH` = `0x20000`, because `CHIP_ID` is at `0x1FFF8`). `GLOBAL_RESET` (`0x10`) accepts `0x7041776` and calls `runtime_request_reboot()`; the runtime then stops T1 and invokes `Havn_Reboot` on T0. Other writes are ignored. `PERICLKSET0/1` set bits and `PERICLKCLR0/1` clear bits in a 48-entry clock-enable array; reads on any of the four return the current enabled mask. `PWRDN_SCRATCH0..31` (`0xA0..0x11C`) back a 32-entry array, and `PWRDN_SCRATCH_LOCK0..1` (`0x120..0x124`) lock scratch 0-15. `LONG_LIFE_SCRATCH0..3` (`0x12C..0x138`) are gated by `LONG_LIFE_SCRATCH_WR_EN` (`0x128`, all bits on by default). `RST_WR_EN0/1` (`0x90`, `0x98`) default enabled and gate `RST0/1` writes, which are logged but have no reset action yet. `RSTSRC` (`0xC`) reads 0 and ignores writes; `CLRRST` (`0x8`) clears it on a nonzero write. `LOW_POWER_DIS` (`0x14`), `EXITPD_MASK` (`0x4C`), and `INT_ENABLE` (`0x13C`) are basic registers; `CHIP_ID` (`0x1FFF8`) reads `0x4485694D` and ignores writes. The rest of the low register block (`0x0..0x13C`) plus `INT_STATE`/`INT_TEST`/`ANTEST_TOP_CTRL`/`ANTEST_REGDIG` are storage. It runs inline.
- `PINMUX` is mapped at `REG_PINMUX_BASE_ADDR` (`0x40060000`, size `DEFAULT_REG_LENGTH`). The full `0x0..0x290` register file lives in one array: paired SEL/CTL pads at `0x0..0xF4`, GPIO0/1 SELs at `0xF8..0x174`, other SELs at `0x178..0x280`, and `EXITEN0`/`EXITEDGE0`/`EXITINV0`/`HOLD` at `0x284..0x290`. SEL writes above `0x63` are rejected and logged, and CTL pull-up/pull-down conflicts are logged. `PINMUX_GetGpioPad(bank, pin)` resolves the pad routed to a GPIO, and `PINMUX_PadLevel()` returns the pad level from its CTL pull bits or the external strap table. The strap table marks DIOA1 and DIOA9 as weak pull-ups, DIOA6 and DIOA12 as weak pull-downs, and DIOM3 as the AP reset line, which is what `get_strap_config()` and `init_ap_detect()` sample. `PINMUX_SetPadLevel()` overrides a pad level; RBOX uses it to drive DIOM3 when `ASSERT_EC_RST` is written, which models the AP entering and leaving reset. It runs inline; other pad physics are not modeled.

- `UART0/1/2` are mapped at `0x40600000`, `0x40610000`, and `0x40620000` (size `DEFAULT_REG_LENGTH`) with separate state. `NCO`, `ICTRL`, `FIFO`, `ISTATE`, `RFIFO`, `OVRD`, `VAL`, `RXTO`, and `ITCR`/`ITOP` are storage; `CTRL`, `STATE`, `RDATA`, `WDATA`, `ISTATECLR`, and `STATECLR` are custom. `STATE` bit 7 tracks RX empty: reads poll the pty master and clear it when a byte is buffered, which is what the loader's `uart_rx_ready()` checks before `RDATA`. UART0 is the console: with `--console stdio` or `--console pty`, `WDATA` writes the pty master and `RDATA` reads it; `pty` leaves stdio unattached for external tools; without a console, `WDATA` writes stdout and `RDATA` returns 0. RX bytes pend IRQ 174 and TX bytes pend IRQ 177. UART0 has a poll callback: `UART_Poll` checks the pty every 64 blocks, buffers a received byte, and pends the RX IRQ, so console input reaches the guest even while it sleeps. UART0 also scans its TX stream for the firmware's `generated challenge:` banner and captures the 80-character challenge. `rma.c` searches SRAM for that challenge, finds the adjacent 8-character auth-code buffer, and emits the code through `LOG()` so the user can feed it back to `rma_auth`. UART1/2 are silent stubs. UART0 registers with `component_register_threaded`; UART1/2 run inline.
- `SWDP` is mapped at `REG_SWDP_BASE_ADDR` (`0x40520000`, size `DEFAULT_REG_LENGTH`). `P4_LAST_SYNC` (`0x2C`), `BUILD_DATE` (`0x30`), and `BUILD_TIME` (`0x34`) are read-only `BasicRegister` entries that read 0; writes are logged and ignored. The trickbox, scratch, `APPSVTOR`, MD5, and test-port registers are read/write storage. It runs inline.
- `TRNG` is mapped at `REG_TRNG_BASE_ADDR` (`0x40410000`, size `DEFAULT_REG_LENGTH`). `SECURE_POST_PROCESSING_CTRL` (`0x10`), `POST_PROCESSING_CTRL` (`0x14`), `GO_EVENT` (`0x18`), `TIMEOUT_COUNTER` (`0x1C`), `TIMEOUT_MAX_TRY_NUM` (`0x20`), `OUTPUT_TIME_COUNTER` (`0x24`), `STOP_WORK` (`0x28`), `FSM_STATE` (`0x2C`), `ALLOWED_VALUES` (`0x30`), `SLICE_MAX_UPPER_LIMIT` (`0x38`), `SLICE_MIN_LOWER_LIMIT` (`0x3C`), `LDO_CTRL` (`0x48`), `POWER_DOWN_B` (`0x4C`), `ANALOG_CTRL` (`0x64`), and `EMPTY` (`0x7C`) are `BasicRegister` entries. `READ_DATA` (`0x70`) returns 32 bits from `getrandom()`; writes are logged and ignored. `VERSION` reads `0x1014125`, `INT_STATE` is write-1-to-clear, and the remaining interrupt, timer, analog, and one-shot registers are storage. It registers with `component_register_threaded`.
- `XO` is mapped at `REG_XO_BASE_ADDR` (`0x400B0000`, size `DEFAULT_REG_LENGTH`). The full `0x0..0x220` control/trim/calibration/bank register file is one storage array; `VERSION` reads `0x101424A` and `DXO_INT_STATE` is write-1-to-clear. It runs inline.
- `RTC` is mapped at `REG_RTC_BASE_ADDR` (`0x400A0000`, size `DEFAULT_REG_LENGTH`). `CTRL`, `PINMUX_EN`, `PULSE_STRETCH`, `SW_TRIM_EN`, and `SW_TRIM_COUNTER` are storage; it runs inline.
- `TIMEHS0` and `TIMEHS1` are mapped at `REG_TIMEHS0_BASE_ADDR` (`0x40650000`) and `REG_TIMEHS1_BASE_ADDR` (`0x40660000`), size `DEFAULT_REG_LENGTH`. Each CMSDK dual timer exposes the two load/value/control/intclr/ris/mis/bgload register groups (`0x0..0x38`), `ITCR`/`ITOP`, and the peripheral/cell ID registers. `VALUE` counts down at 24 MHz from `LOAD`/`BGLOAD`, `RIS`/`MIS` reflect expiry, `INTCLR` clears and unpends, and expiry pends IRQs 153-155 (TIMEHS0) or 156-158 (TIMEHS1). `TIMEHS_Poll` runs from the M3 block hook. Prescale bits and free-running interrupt timing are not modeled yet.
- `TIMELS` is mapped at `REG_TIMELS_BASE_ADDR` (`0x40540000`, size `DEFAULT_REG_LENGTH`). Two countdown timers at `0x0` and `0x40` model `CONTROL`, `STATUS`, `LOAD`, `RELOADVAL`, `VALUE`, `STEP`, `IER`, `ISR`, `IPR`, `IAR`, and `WAKEUP_ACK` at 262144 Hz. Enabling a timer clears its expiry status, and `STATUS`/`ISR`/`IPR`/`IAR`/`WAKEUP_ACK` writes clear it too, so a serviced timer IRQ does not stay pending. A block hook calls `TIMELS_Poll()`, which reloads/wraps timers and pends IRQ 159/160 when `IER` is set; it runs inline.
- `WATCHDOG` is mapped at `REG_WATCHDOG_BASE_ADDR` (`0x40500000`, size `DEFAULT_REG_LENGTH`). `WDOGLOAD`, `WDOGVALUE`, `WDOGCONTROL`, `WDOGINTCLR`, `WDOGRIS`, `WDOGMIS`, `WDOGLOCK`, `WDOGITCR`, `WDOGITOP`, and the ID registers are storage. It never resets the emulator; it runs inline.
- `RBOX` is mapped at `REG_RBOX_BASE_ADDR` (`0x40550000`, size `DEFAULT_REG_LENGTH`). The `0x0..0xA0` register file is one array; `INT_STATE` (`0x4`) is write-1-clear and `VERSION` (`0xA0`) reads `0x1014125`. It runs inline.
- `CRYPTO` is mapped at `REG_CRYPTO_BASE_ADDR` (`0x40420000`, size `DEFAULT_REG_LENGTH`). The `0x0..0x50` control register file and the 1024-word `IMEM`/`DMEM` windows are modeled. Before running the legacy `0x343` modload entry, the handler rewrites the `ldi r3,[#6]` mask load to the newer zero-and-immediate sequence; 2016 images overwrite DMEM cell 6 with modulus data, which otherwise makes `computeRR` loop forever. `CONTROL` reset and `WIPE_SECRETS` reset the engine and clear status; `HOST_CMD` takes `0x08000000 + IMEM index`, runs the accelerator until it halts, sets `INT_STATE.HOST_CMD_RECV`/`HOST_CMD_DONE`, and pends IRQ 4; `INT_STATE` is write-1-to-clear. `crypto-engine.c` is the bignum program interpreter: 32 wide registers, DMEM/IMEM, add/sub/mul128/and/or/not/xor/shift/select/compare, modular add/sub, special registers (`rfp`, `dmp`, `lc`, `rnd`, `mod`), indexed load/store, calls, loops, branches, and sign/hash stubs. It runs inline.
- `RDD` is mapped at `REG_RDD_BASE_ADDR` (`0x40440000`, size `DEFAULT_REG_LENGTH`). `VERSION`, `INT_ENABLE`, `INT_STATE`, `INT_TEST`, `POWER_DOWN_B`, `ANTEST`, the wait-time counters, `REF_ADJ`, `INPUT_PIN_VALUES`, `PROG_DEBUG_STATE_MAP`, and `CUR_STABLE_STATE` are storage; CCD bring-up only needs the writes to land and read back. It runs inline.
- `SPI` is mapped at `REG_SPI_BASE_ADDR` (`0x40700000`, size `DEFAULT_REG_LENGTH`). `CTRL`, `XACT`, `ICTRL`, `ISTATE`, `ISTATE_CLR`, `OVRD`, `VAL`, `ITCR`, `ITOP`, `TX_DATA`, and `RX_DATA` are storage. A `XACT.START` write sets `ISTATE.TXDONE` and copies the last `TX_DATA` word to `RX_DATA`; `ISTATE_CLR` clears the done bit. It runs inline.
- `SPS` is mapped at `REG_SPS_BASE_ADDR` (`0x40510000`, size `DEFAULT_REG_LENGTH`). It models the TPM SPI slave: `CTRL`, `DUMMY_WORD`, the `STATUS`/`CTRL` array registers, 4 KiB TX/RX FIFOs at `0x1000`/`0x1400`, 11-bit read/write pointers, thresholds, `OVRD`, `VAL` MISO/MOSI/CSB bits, `ISTATE`/`ISTATE_CLR`/`ICTRL`, IRQs 129, 130, 138, 139, 148, 149, 150, and the EEPROM/flash-controller block (`0x400..0x580`, storage with a write-1-to-clear `EEPROM_INT_STATE`). `tpm-proxy.c` drives chip select and FIFO transfers through `SPS_HostSetChipSelect`/`SPS_HostTransfer`, which serialize on the SPS worker. It registers with `component_register_threaded`. The proxy re-sends TPM2_Startup before forwarded commands when the guest TPM was reset, which keeps `/dev/tpmN` usable across `ccd open`.

- `GPIO0` and `GPIO1` are mapped at `REG_GPIO0_BASE_ADDR` (`0x40200000`) and `REG_GPIO1_BASE_ADDR` (`0x40210000`), size `DEFAULT_REG_LENGTH`. Each bank has independent `DOUT`, `SET/CLRDOUTEN`, `SET/CLRINTEN`, `SET/CLRINTTYPE`, `SET/CLRINTPOL`, `CLRINTSTAT`, `RESERVED0/1`, and 256-entry `MASKLOWBYTE`/`MASKHIGHBYTE` arrays. `DATAIN` reads the pad level for each pin: an enabled output drives `DOUT`, a `GPIO_SetInputOverride()` pin uses its forced level, otherwise `PINMUX_PadLevel()` applies the pad's internal pull or its external strap level. The USB proxy forces `GPIO0.5` low to assert the CCD strap before emulation starts. `Havn_Initialize` forces `GPIO0.6` (`BATT_PRES_L`) high, so the firmware sees the battery as removed and `ccd open` skips the physical-presence check, and forces `GPIO0.12`/`GPIO0.13` (`I2C_SCL_INA`/`I2C_SDA_INA`) high so the I2C bus is idle. Edge and level interrupts are modeled: `GPIO_Poll` samples both banks from the M3 block hook, pends the per-pin IRQ (65+pin or 82+pin) and the combined IRQ (81/98), and `CLRINTSTAT` unpends them. `GPIO_Refresh` samples immediately after a pad override. They run inline.

- `I2C0` and `I2C1` are mapped at `REG_I2C0_BASE_ADDR` (`0x40630000`) and `REG_I2C1_BASE_ADDR` (`0x40640000`), size `DEFAULT_REG_LENGTH`. `I2CS` is mapped at `REG_I2CS_BASE_ADDR` (`0x40530000`). The controller register file (`0x0..0x7C`) plus `ITCR`/`ITOP` (`0xF00`/`0xF04`) is storage, with `INST` transactions completing with `CA_NACK` because no bus devices are modeled; the slave file (`0x0..0xB0`) is storage with the hardware `VERSION`/`CTRL_SDA_VAL`/`CTRL_MSR` defaults. IRQs 99/100 are not pended because the driver polls `STATUS.INTB`.
- `USB` is mapped at `REG_USB_BASE_ADDR` (`0x40300000`, size `DEFAULT_REG_LENGTH`). It models the DWC OTG device controller used by `chip/g/usb.c`: global/device registers, 16 IN and 16 OUT endpoint register blocks (`0x900`/`0xB00`, stride `0x20`), endpoint TX FIFO sizes (`0x104..0x13C`), scatter/gather DMA descriptors, EP0 control transfers, and bulk IN/OUT. `GINTSTS` is write-1-to-clear, `GRSTCTL` reads `AHBIDLE` and `CSFTRST` resets the endpoint state, `DAINT` is derived from the endpoint interrupt flags, and the block pends IRQ 193 when `GAHBCFG.GLBLINTRMSK` and an unmasked status bit are set. Host events are queued by `usb-proxy.c` through `USB_Host*()` and drained by `USB_Poll()` from the M3 block hook; DMA descriptor and buffer access happen on the emulation thread. `DCTL.SFTDISCON` connects/disconnects the raw-gadget link. Offsets outside the register map fault through `component_log_unhandled`.
- `KEYMGR` is mapped at `REG_KEYMGR_BASE_ADDR` (`0x40570000`, size `DEFAULT_REG_LENGTH`). It implements the full SHA register file (`CFG_MSGLEN`, `CFG_EN`, `CFG_WR_EN`, `TRIG`, `INPUT_FIFO`, `STS_H`, `KEY_W`, `STS`, `ITCR`, `ITOP`, `USE_HIDDEN_KEY`, `USE_CERT`, `CERT_OVERRIDE`, `RAND_STALL_CTL`, `EXECUTE_COUNT_STATE/MAX`) using `common/sha256.c`, plus `HKEY_RWR0..7`, `RWR_VLD`, `RWR_LOCK`, `HKEY_FWR0..7`, `FWR_VLD`, `FW_MAJOR_VERSION`, `FWR_LOCK`, `HKEY_FRR0..7` (writes ignored), `HKEY_ERR_FLAGS`, and `CERT_REVOKE_CTRL0..2`. The engine streams the input FIFO into one SHA context, so message length is unbounded. One-shot mode finalizes when `CFG_MSGLEN` bytes arrive; livestream mode (`CFG_EN` bit 4) finalizes on `TRIG` stop (bit 3). A `TRIG` go with `USE_CERT` enabled completes immediately, matching upstream's unsupported-cert path. `CFG_EN` bit 5 selects HMAC-SHA256 and uses `KEY_W0..7` as the key. `CFG_EN` bit 1 (SHA1) is not implemented. `CERT_REVOKE_CTRL0..2` read the hardware defaults (`0xA8028A82`, `0xAAAAAAAA`, `0xAAAA`) and ignore writes, so `DCRYPTO_ladder_is_enabled()` stays true. The test-mode password, `HKEY_HWR`, `HWR_VLD`/`HWR_LOCK`, flash-receive, error-control, and SHA FIFO interrupt registers are storage; `INT_STATE` is write-1-to-clear.
- `KEYMGR` also implements the AES engine at `0x0..0xC0`: `CTRL` (`RESET`, `ENABLE`, key size 128/192/256, ECB/CTR/CBC mode, encrypt/decrypt, CTR endianness), `KEY0..7`, `KEY_START` (expands the key and reads back 0), `CTR0..3`, `WFIFO_DATA`/`RFIFO_DATA` with level/full/empty mirrors, `GCM_H`/`GCM_MAC`/`GCM_HASH_IN`/`GCM_DO_ACC`, `WIPE_SECRETS`, `INT_ENABLE`/`INT_STATE`/`INT_TEST`, and `USE_HIDDEN_KEY`. Blocks are ciphered as soon as four `WFIFO_DATA` words are buffered; results land in `RFIFO_DATA` four words at a time. `common/aes.c` is the block cipher. `USE_HIDDEN_KEY.ENABLE` uses a zero key instead of a real hidden key. AES status bits are sticky and write-1-to-clear; AES IRQs are not pended. It registers with `component_register_threaded`; the SHA and AES engines run on the KEYMGR worker.

- `FLASH` is mapped at `REG_FLASH_BASE_ADDR` (`0x40720000`, size `DEFAULT_REG_LENGTH`). `PE_EN` must hold `0xB11924E1` before a `PE_CONTROL0/1` opcode runs; the opcode is cleared after execution. `TRANS` carries the word offset, main/INFO bank, and count-minus-one. The controller implements read (`0x16021765`, one word into `DOUT_VAL0/1`), row-program (`0x27182818`, AND `WR_DATA` into the bank, row-aligned), page erase (`0x31415927`, 2 KiB of `0xFF`), and bulk erase (`0x1D1E2BAD`, 256 KiB main bank or 2 KiB INFO bank). Control 0 addresses the first main/INFO half, control 1 the second. Main-bank reads go straight to the mapped PROG region. `ERROR` reports row-alignment, range, page-alignment, INFO1-lock, and invalid-access bits and clears 5 ms after the last error. The three `TIMING_*_SMART_ALGO_ON` registers read 1 and ignore writes, matching the hardware default the flash driver requires. The override, shadow-read, interrupt, and no-wait registers are storage; `ISTATE` is write-1-to-clear. Program/erase hit `ctx.uc` memory directly. It runs inline.

- MMIO handlers must not call `emu_exit` or `uc_close`; use `runtime_fault` from any thread and let the control thread clean up. `Havn_StartEmulation` must not exit on runtime errors.

Known gaps (these fault, they do not silently succeed):

- `M3`: MPU, ITCM, `DebugMonitor`/`PendSV` pending, and reset/NMI delivery are not modeled. Unmapped or protected memory stays fatal instead of escalating to a fault handler, by design.
- `KEYMGR`: SHA1 (`CFG_EN` bit 1) is not implemented, AES `CIPHER_MODE` 3 (GCM) does not cipher blocks, hidden-key mode substitutes a zero key, and AES status bits do not pend IRQs.
- `FLASH`: smart-algorithm timing and the hardware error log are not modeled.
- `CRYPTO`: the wide-register file stops at 256 bits, a loop with a zero count skips its body instead of wrapping to 2^64 iterations, and a program that exceeds the step limit stops with an error instead of running forever.
- `GLOBALSEC`: an expired shutdown delay reports a runtime fault; it does not reset the emulated chip.
- `GPIO`: only the strap and AP reset pads have external levels; other pad physics and GPIO wake behavior are not modeled.
- `USB`: descriptors, control transfers, the console, and the upgrade endpoints work through `dummy_hcd`/`raw-gadget`. The CCD `EXTENSION_POST_RESET` frame on endpoint 4 now requests a full chip reboot through `runtime_request_reboot()`.
- `TIMEHS`: prescale bits and exact free-running interrupt timing are not modeled; the dual timer counts down from wall time at 24 MHz.
- `I2C`: the controller NACKs every transaction because no I2C peripherals are modeled; `i2cscan` reports an empty bus. The slave interface is register storage only.
- `RMA`: the auth code is found by scanning SRAM for the printed challenge and reading the nearby bounded 8-character base32 run. This assumes the firmware keeps the challenge and auth-code buffers in SRAM and adjacent, which the current RW image does. The code cannot be recomputed from the challenge alone because its HMAC key is the ephemeral ECDH shared secret.

Do not add a catch-all range to make a known gap pass. Add the register and its behavior, or leave the fault in place.
- Plain registers use `DEFINE_BASIC_REGISTER(name)` for storage plus a `BASIC_REGISTER_ENTRY(offset, name)` row in a `static const BasicRegister <component>_registers[]`; `basic_register_find(array, ARRAY_LEN(array), offset)` dispatches read and write from that row. Keep switch cases only for side effects (`ITCMCR` write-back, future UART `CTRL` state), read-only/constant values (`CPUID`), validation/table lookup (`PINMUX`, `FUSE`), or per-instance/array state. Use `Component.state` for per-instance state.
- `Havn_StartEmulation` and `Havn_EndEmulation` must not call `exit`. Return normally, or use `runtime_fault` for runtime errors.
- `Havn_EndEmulation` runs on T0 after the emulation thread and workers have stopped, and must tolerate a partially initialized backend because failure paths call it through `emu_exit`.
- Keep Haven state, register definitions, and chip-specific parsing in this module. Do not add them to `common/Emulator`.
- Use `LOG`, `LOG_VBS`, and `LOG_ERR`; do not call `printf` directly.
- New chips follow the same shape:
  1. add an `EmulatorChips` value in `include/common/emulator.h`
  2. add `include/<CHIP>/emulator.h` and `src/<CHIP>/emulator.c`
  3. add a `case` in `get_chipemu`
  4. add `include/<CHIP>/memory.h` and `src/<CHIP>/memory.c` with the essential memory table; assign it to `ctx.essential_memory`, call `map_essential_memory()`, then `load_firmware()`
  5. add `include/<CHIP>/peripherals.h` with `DEFAULT_REG_LENGTH`, one `include/<CHIP>/peripherals/<name>.h` per peripheral, and `src/<CHIP>/peripherals/`
  6. add `src/<CHIP>/firmware/{bootrom,firmware}.bin` and the matching `BUNDLED_<CHIP>_*` arrays under `#ifdef BUNDLED_<CHIP>`
  7. add the chip to `BUNDLED_CHIPS` in the Makefile
  8. update the `--chip` help text, default selection if needed, and `tests/fuzz.dict`
- Do not advertise `h1c3m`, `h1d3c`, `h1d3m`, or `npcx` as working until their backends exist and have been smoke-tested.

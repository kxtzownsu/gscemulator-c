# src/H1B3C

H1B3C is the Haven chip backend. Its entry points use the `Havn_` prefix.

- Public hooks are declared in `include/H1B3C/emulator.h` and wired through `get_chipemu` in `src/main.c`.
- `Havn_Initialize(void)` must set `ctx.chipemu.ready = true` only after setup succeeds. `main` exits through `emu_exit` when `ready` is false.
- `Havn_Initialize` stores the engine in `ctx.uc`; `Havn_EndEmulation` closes it and clears the pointer so repeated calls are safe.
- `Havn_Initialize` uses `ctx.firmware.bootrom` when `ctx.firmware.useBundledROM` is false. With `BUNDLED_H1B3C` defined, it sets `useBundledROM`/`useBundledFW` when the matching path is empty, and `load_firmware` copies `BUNDLED_H1B3C_BOOTROM_BIN`/`BUNDLED_H1B3C_FIRMWARE_BIN` into the ROM/firmware regions. A failed read or oversized bundle exits with `RC_CHIPEMU_FAILED_INIT`.
- `H1B3C_EssentialMemoryArray` in `src/H1B3C/memory.c` lists ROM (RX), SRAM (RW), INFO0/INFO1 (RW), and PROG (RWX). ROM and PROG are marked `ESSENTIAL_MEMORY_ROM` and `ESSENTIAL_MEMORY_FIRMWARE`.
- `Havn_Initialize` assigns the table to `ctx.essential_memory`, calls `map_essential_memory()`, then calls `load_firmware()` with the `BUNDLED_H1B3C_*` arrays under `BUNDLED_H1B3C` or NULLs when H1B3C is not bundled. INFO1 remains a chip-local write.
- `Havn_Initialize` calls `set_sp_pc(ctx.uc, FLASH_ROM_BASE)` after the flash writes. `set_sp_pc` sets SP/PC; `Havn_StartEmulation` sets the Thumb bit.
- `init_unicorn` installs the memory fault hook after `uc_open` and the Cortex-M3 model setup, so unmapped/protected accesses log the address, access type, and PC.
- `Havn_StartEmulation` runs on T1, checks `memory_fault_occurred()` after `uc_emu_start`, and reports failures with `runtime_fault` before inspecting the engine error. It returns instead of exiting.
- `ctx.firmware.progfw` / `--firmware` is loaded into the firmware region by `load_firmware`.
- Peripherals live in `src/H1B3C/peripherals/`. Each `X_Initialize()` registers a `Component` and `initialize_peripherals()` maps the `MmioRegion` table before `ready` is set. `component_register_threaded` starts an opt-in worker; `component_register` keeps the handler inline on T1.
- Register bases and offsets belong in the matching `include/H1B3C/peripherals/<name>.h`; `DEFAULT_REG_LENGTH` in `H1B3C/peripherals.h` is the MMIO region size for every peripheral. Keep offsets 4-byte aligned.
- `M3` is mapped at `REG_M3_BASE_ADDR` (`0xE0000000`, size `DEFAULT_REG_LENGTH`) and handles `DWT_CTRL`, `DWT_CYCCNT` (reads 0), `CPUID`, `VTOR`, `ITCMCR`, and `DEMCR`. `CPUID` reads `0x410FC331` and is read-only; `ITCMCR` reads back `7` after any write, matching the Cr50 ROM.
- `FUSE` is mapped at `REG_FUSE_BASE_ADDR` (`0x40450000`, size `DEFAULT_REG_LENGTH`). Reads return the matching `fuse_defaults` value or `REG_FUSE_BLANK_VALUE` (`0x55555555`); writes are ignored and only logged at verbose level, matching the read-only eFuse.
- `GLOBALSEC` is mapped at `REG_GLOBALSEC_BASE_ADDR` (`0x40090000`, size `DEFAULT_REG_LENGTH`). The region/permission window `0x0..0x2DC` is one storage array; `ALERT_INTR_STS0/1`, `ALERT_CONTROL`, and `DBG_CONTROL` are basic registers; `DUMMYKEY0..2` (`0x9598`, `0xAF04`, `0xB2AC`) back an array. `SB_COMP_STATUS`, `SB_BL_SIG0..7`, and `SIG_UNLOCK` are custom; `SIG_UNLOCK` forces `SB_COMP_STATUS` true to skip the RSA path, matching upstream's force setting. `HIDE_ROM` (`0x40D0`) is write-once: once set, later writes are ignored.
- `PMU` is mapped at `REG_PMU_BASE_ADDR` (`0x40000000`, size `DEFAULT_REG_LENGTH`). `PERICLKSET0/1` set bits and `PERICLKCLR0/1` clear bits in a 48-entry clock-enable array; reads on any of the four return the current enabled mask. `PWRDN_SCRATCH0..31` (`0xA0..0x11C`) back a 32-entry array, and `PWRDN_SCRATCH_LOCK0..1` (`0x120..0x124`) lock scratch 0-15. `LONG_LIFE_SCRATCH0..3` (`0x12C..0x138`) are gated by `LONG_LIFE_SCRATCH_WR_EN` (`0x128`, all bits on by default). `RST_WR_EN0/1` (`0x90`, `0x98`) default enabled and gate `RST0/1` writes, which are logged but have no reset action yet. `RSTSRC` (`0xC`) reads 0 and ignores writes. It runs inline; the remaining PMU registers are next.
- `PINMUX` is mapped at `REG_PINMUX_BASE_ADDR` (`0x40060000`, size `DEFAULT_REG_LENGTH`). The full `0x0..0x290` register file lives in one array: paired SEL/CTL pads at `0x0..0xF4`, GPIO0/1 SELs at `0xF8..0x174`, other SELs at `0x178..0x280`, and `EXITEN0`/`EXITEDGE0`/`EXITINV0`/`HOLD` at `0x284..0x290`. SEL writes above `0x63` are rejected and logged, and CTL pull-up/pull-down conflicts are logged. It runs inline; pin-device routing and pad physics land with GPIO/SPS/UART.
- `UART` is mapped at `REG_UART_BASE_ADDR` (`0x40600000`, size `DEFAULT_REG_LENGTH`). `NCO` (`0x8`) is a `BasicRegister` entry; `CTRL` (`0xC`), `STATE` (`0x14`), `RDATA` (`0x0`), and `WDATA` (`0x4`) are custom. CTRL sets the TX/RX STATE bits, WDATA writes a byte to stdout, and RDATA returns 0 until console input exists. It registers with `component_register_threaded`; pty/console wiring and interrupts land next.
- `SWDP` is mapped at `REG_SWDP_BASE_ADDR` (`0x40520000`, size `DEFAULT_REG_LENGTH`). `P4_LAST_SYNC` (`0x2C`), `BUILD_DATE` (`0x30`), and `BUILD_TIME` (`0x34`) are read-only `BasicRegister` entries that read 0; writes are logged and ignored. It runs inline.
- `TRNG` is mapped at `REG_TRNG_BASE_ADDR` (`0x40410000`, size `DEFAULT_REG_LENGTH`). `POST_PROCESSING_CTRL` (`0x14`), `GO_EVENT` (`0x18`), `OUTPUT_TIME_COUNTER` (`0x24`), `SLICE_MAX_UPPER_LIMIT` (`0x38`), `SLICE_MIN_LOWER_LIMIT` (`0x3C`), `LDO_CTRL` (`0x48`), `POWER_DOWN_B` (`0x4C`), and `ANALOG_CTRL` (`0x64`) are `BasicRegister` entries; `READ_DATA` (`0x70`) reads 0. It registers with `component_register_threaded`; the entropy path lands next.
- `XO` is mapped at `REG_XO_BASE_ADDR` (`0x400B0000`, size `DEFAULT_REG_LENGTH`). `CLK_JTR_SYNC_CONTENTS` (`0x1C`) is a `BasicRegister`; it runs inline.
- `GPIO` is mapped at `REG_GPIO_BASE_ADDR` (`0x40200000`, size `DEFAULT_REG_LENGTH`). `DATAIN` (`0x0`) reads 0 so `check_engage_spiflash()` stays on the normal verified-boot path; it runs inline.
- `KEYMGR` is mapped at `REG_KEYMGR_BASE_ADDR` (`0x40570000`, size `DEFAULT_REG_LENGTH`). It implements the full SHA register file (`CFG_MSGLEN`, `CFG_EN`, `CFG_WR_EN`, `TRIG`, `INPUT_FIFO`, `STS_H`, `KEY_W`, `STS`, `ITCR`, `ITOP`, `USE_HIDDEN_KEY`, `USE_CERT`, `CERT_OVERRIDE`, `RAND_STALL_CTL`, `EXECUTE_COUNT_STATE/MAX`) using `common/sha256.c`, plus `HKEY_RWR0..7`, `RWR_VLD`, `RWR_LOCK`, and `HKEY_ERR_FLAGS`. The engine streams the input FIFO into one SHA context, so message length is unbounded. One-shot mode finalizes when `CFG_MSGLEN` bytes arrive; livestream mode (`CFG_EN` bit 4) finalizes on `TRIG` stop (bit 3). A `TRIG` go with `USE_CERT` enabled completes immediately, matching upstream's unsupported-cert path. It registers with `component_register_threaded`; the SHA engine runs on the KEYMGR worker.
- `FLASH` is mapped at `REG_FLASH_BASE_ADDR` (`0x40720000`, size `DEFAULT_REG_LENGTH`). `TRANS`, `PE_EN`, `PE_CONTROL0/1`, `ERROR`, `DOUT_VAL0/1`, and `WR_DATA` are enough for `flash_info_read()`; INFO reads return `0xffffffff`, matching blank INFO1. It runs inline.
- MMIO handlers must not call `emu_exit` or `uc_close`; use `runtime_fault` from any thread and let the control thread clean up. `Havn_StartEmulation` must not exit on runtime errors.
- Plain registers use `DEFINE_BASIC_REGISTER(name)` for storage plus a `BASIC_REGISTER_ENTRY(offset, name)` row in a `static const BasicRegister <component>_registers[]`; `basic_register_find(array, ARRAY_LEN(array), offset)` dispatches read and write from that row. Keep switch cases only for side effects (`ITCMCR` write-back, future UART `CTRL` state), read-only/constant values (`CPUID`), validation/table lookup (`PINMUX`, `FUSE`), or per-instance/array state. Use `Component.state` for per-instance state.
- `Havn_StartEmulation` and `Havn_EndEmulation` must not call `exit`. Return normally, or use `runtime_fault` for runtime errors.
- `Havn_EndEmulation` runs on T0 after the emulation thread and workers have stopped, and must tolerate a partially initialized backend because failure paths call it through `emu_exit`.
- Keep Haven state, register definitions, and chip-specific parsing in this module. Do not add them to `common/Emulator`.
- Use `LOG`, `LOG_VBS`, and `LOG_ERR`; do not call `printf` directly.
- New chips follow the same shape:
  1. add an `EmulatorChips` value in `include/common/emulator.h`
  2. add `include/<CHIP>/emulator.h` and `src/<CHIP>/emulator.c`
  3. add a `case` in `get_chipemu`
  4. add `include/<CHIP>/memory.h` and `src/<CHIP>/memory.c` with the essential memory table; assign it to `ctx.essential_memory`, call `map_essential_memory()`, then `load_firmware()`
  5. add `include/<CHIP>/peripherals.h` with `DEFAULT_REG_LENGTH`, one `include/<CHIP>/peripherals/<name>.h` per peripheral, and `src/<CHIP>/peripherals/`
  6. add `src/<CHIP>/firmware/{bootrom,firmware}.bin` and the matching `BUNDLED_<CHIP>_*` arrays under `#ifdef BUNDLED_<CHIP>`
  7. add the chip to `BUNDLED_CHIPS` in the Makefile
  8. update the `--chip` help text, default selection if needed, and `tests/fuzz.dict`
- Do not advertise `h1c3m`, `h1d3c`, `h1d3m`, or `npcx` as working until their backends exist and have been smoke-tested.

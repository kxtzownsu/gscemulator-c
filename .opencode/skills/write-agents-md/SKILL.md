# Write AGENTS.md

This repo uses layered `AGENTS.md` files. The closest file to the edited path wins, and the root file still applies. Keep each level focused on what is local to it.

## Root file

`AGENTS.md` should stay short and cover only what applies everywhere:

- One-sentence project description and current status.
- Exact commands: build, clean, run, fuzz, verify.
- Module map, not an exhaustive file tree.
- Runtime contracts: CLI, `libargs`, `Emulator` lifecycle.
- Security rules: untrusted formats, allocation checks, opaque APIs, no host I/O.
- C and Makefile style.
- Verification commands and the commit-message format.
- Working rules and boundaries.

Keep the root under about 150 lines. Link to nested files instead of repeating module rules.

## Nested files

Current modules:

- `include/AGENTS.md` - public headers, opaque APIs, prototype sync.
- `src/common/AGENTS.md` - `ctx`, `emu_exit`, `Rc`, file helpers, logger, chip-agnostic interface.
- `src/H1B3C/AGENTS.md` - Haven backend, `ready` contract, new-chip steps.
- `tests/AGENTS.md` - fuzz harness, corpus, dictionary, help filtering.

A nested file should contain only module-specific rules and gotchas. Do not copy the root code style or commit rules into every module.

## Project-specific facts to preserve

- `argcheck_fequals` and `argcheck_fequals_str` return pointers valid only until `argcheck_destroy`.
- `argcheck_destroy` is not idempotent and prints help/exits on `-h`/`--help`.
- `emu_exit` is `_Noreturn`, takes an `Rc`, stops workers and the console, and destroys `ctx.ac`. It is control-thread-only; MMIO and worker paths use `runtime_fault`.
- `common/runtime/control.h` owns the control loop, fault mailbox, emulation thread, and teardown. `runtime_fault` is callable from any thread and only records + stops; T0 exits.
- `common/runtime/thread.h` owns `tctx`, a thread-local role/label/PC record. Never store `ctx.uc`, `ctx.ac`, or the component array in it.
- `common/ctx.h` holds the global `Ctx` and `ctx_init` zeroes it.
- `common/rc.h` defines every exit code; no raw numbers.
- `common/file.h` returns `FileRC`; the helpers log, never call `emu_exit`, and count the trailing NUL in `buffer_size`.
- `ctx.firmware` paths are fixed `char[MAX_FILE_PATH]` buffers with `useBundledROM`/`useBundledFW`; `main` fills the paths from `--bootrom`/`--firmware` and the backend sets the bundled flags when its `BUNDLED_<CHIP>` macro is defined and the path is empty. Copy CLI strings in with `snprintf` and reject truncation.
- Each chip exposes an `EssentialMemoryEntry` table with an empty `NAME` terminator; mark one ROM and one firmware role, map it via `ctx.essential_memory` + `map_essential_memory` before flash writes, then call `load_firmware` to pre-fill and load the ROM/firmware regions.
- `set_sp_pc(uc, vtor_base)` reads SP at offset `0x0` and PC at `0x4` and writes the ARM registers; it does not set the Thumb bit.
- `install_memory_fault_hook` logs unmapped/protected memory reads, writes, and fetches with address and PC, then sets an atomic fault flag and stops emulation. Hook callbacks must not call `emu_exit` or `uc_close`; T1 reports `RC_CHIPEMU_MEMORY_FAULT` through `runtime_fault`.
- `component_log_unhandled` logs an unknown MMIO offset with the component name, access type, and PC, then calls `runtime_fault(RC_CHIPEMU_MEMORY_FAULT, ...)`. On a worker, PC comes from `tctx.mmio_pc`.
- `component_register_threaded` starts an opt-in FIFO worker; `component_register` keeps handlers inline on T1. `component_stop_all` is control-thread-only.
- Plain registers use `DEFINE_BASIC_REGISTER(name)` for storage plus a `BASIC_REGISTER_ENTRY(offset, name)` row in a `static const BasicRegister` table, dispatched by `basic_register_find(array, ARRAY_LEN(array), offset)`. Switch cases are only for side effects, read-only/constant values, validation, or per-instance/array state.
- `make` defaults to `BUNDLED_FIRMWARE=1`, which adds `-DBUNDLED_FIRMWARE` and makes `include/common/bundled-firmware.h` a dependency. `BUNDLED_FIRMWARE=0` is the source-only build.
- `make STATIC=1` links `build/<arch>/unicorn/libunicorn.a` with `third_party/unicorn/include`; the default build uses system pkg-config unicorn.
- `include/common/version.h` is generated by `scripts/generate_version_header.sh` and gitignored; only `src/common/version.c` includes it. `--version` prints the version, toolchain, unicorn, build date, chips, and bundled firmware. A `build/<ARCH>/.build-config` stamp records `STATIC`, `BUNDLED_FIRMWARE`, `BUNDLED_CHIPS`, `CC`, `CHIPS`, and `PROGRAM_VERSION`, so a date-only rebuild does not recompile.
- `PROGRAM_VERSION` is `0.1.0` in `scripts/make/version.mk`; `CHIPS` lists available chips and `BUNDLED_CHIPS` feeds the bundled firmware summary.
- `BUNDLED_CHIPS` selects firmware pairs; the generated header defines `BUNDLED_<CHIP>` plus `BUNDLED_<CHIP>_BOOTROM_BIN` and `BUNDLED_<CHIP>_FIRMWARE_BIN`. Backends gate bundled use on their own `BUNDLED_<CHIP>`, not on `BUNDLED_FIRMWARE`.
- `make clean` removes only `gscemu` and `build/<ARCH>/obj`; `make fullclean` removes the whole `build/<ARCH>` including the local unicorn build.
- Peripheral bases and offsets live per peripheral in `include/H1B3C/peripherals/<name>.h`; `DEFAULT_REG_LENGTH` in `H1B3C/peripherals.h` is the MMIO region size and handler offsets are relative to the region base.
- MMIO callbacks must not call `emu_exit` or `uc_close`; use `runtime_fault`, which is safe from inline and worker handlers. Workers must not call any `uc_*` API.
- `initialize` must set `ctx.chipemu.ready = true` after successful setup.
- `LOG*` messages must be compile-time literals.
- The fuzz harness filters `--help` and `-h` because destroy exits.
- `make run` builds and runs the target directly.
- Only H1B3C is implemented; other chip names are placeholders.

## Workflow

1. Read the root file and the nearest nested file before editing either.
2. Verify every command you add actually works in the current tree.
3. Put cross-cutting rules at the root and module rules in the nearest directory.
4. Remove stale paths, commands, and claims instead of leaving them.
5. Check for contradictions between root and nested files.
6. Do not document generated or ignored paths as source.
